0.8.1 的野怪以已读 `BattleActor.isMonster` 分类和当前 `attribute.curHP` 为依据；仅绘制身份唯一、分类成立、正血量、有当前有效坐标的对象。小兵、建筑、英雄和已确认眼位不作为野怪显示。野怪不参与敌方英雄的头像、血量圈或五人覆盖计数。

野怪标记使用中立颜色，先绘制野怪再绘制英雄，血量文字可通过“隐藏野怪血量”关闭。修改配置后重新启动/更新悬浮窗。诊断的 `minimap.monsters` 和有界追踪的 `monsters` 保存读取与标记结果；未读到的野怪不会显示历史位置或伪造刷新倒计时。

0.8.2 新增敌方技能面板。`drawSkillPanel` 控制显示和额外读取，面板位置/缩放接入原配置；默认位于小地图右侧，位置为 0 时自动布局。`#N` 表示实际技能槽编号，`SN` 表示在召唤师列表中独立确认的槽编号，不代表固定 Q/W/E/R 或某个技能名称。每行最多显示 8 项，超出时用 `+N` 明示，完整数据在诊断中保留。

0.8.5 面板只保留确认的大招（R）和召唤师技能；普通与未知分类条目不显示。召唤师名称按原始资源枚举映射（例如 81090101 闪现、81100101 引燃、81110101 惩戒），未知召唤师名称保留 SN。英雄具体招式名与图标尚未实现。

只展示当前技能与槽位、拥有者匹配的条目。未学习、锁定、不可读分别显示“未学”“锁定”“?”；0.8.2 实测反馈释放后持续为零，0.8.3 将此类未确认零值显示为“待核”，空冷却节点显示“?”；不能据此判断可释放。没有自行推算倒计时；读不到或列表/身份变化时清除原值。整体读到部分数据时明确显示“部分数据”。

诊断与最近的有界追踪新增 `enemy_skill_panel`，包含英雄/技能身份、真实槽号、读取状态、锁定标记和原始 Q14 冷却。原始 getter 读取链路已恢复，实际冷却是否在无视野下持续更新仍需手机日志与画面对照。

0.8.3 冷却诊断新增 `cd_node_address`、`cooldown_source`、`cooldown_zero_verified`、`node_total_fixed`、`node_start_fixed`、`configured_cd1_fixed`、`configured_cd2_fixed` 和独立读取状态。配置 CD1/CD2 只用于诊断，不作为当前剩余冷却。原始 Sync getter 在同步模式下同样读取节点 +0x20，换方法名称不能证明修复。采样心跳与游戏 tick 是不同的新鲜度证据，游戏暂停时心跳仍可能持续。

0.8.3 的技能角色分类使用 UUID 绑定的 FEProj 同步/原生选择器与 GetRSkill 的配置 ID 逆序选择规则，核对 slot.defaultSkill 的身份、槽和拥有者；确认的大招标为 R，普通配置技能标为“技N”，召唤师列表仍标为 SN，未知保持 #N。当时的“隐藏小技能”仅隐藏确认的普通配置技能；完整原始技能仍在 skills 中，display_skills 为当前显示筛选。此分类不提供技能名称或可释放判断。

0.8.4 增加独立逻辑冷却源。原始命名 Lua 属性 BattleActor.skillMgr (0x395dc7c) 读取逻辑英雄 +0x200；原生 GetSkill 通过管理器 +0x2d8/+0x2e0 列表和技能配置资源 ID 查找。资源 ID 必须在当前逻辑列表中唯一，管理器拥有者、逻辑英雄身份、触发器拥有者、当前同步槽和列表在读取后重新核对。原生调用方通过技能 +0x590 取得节点，GetState/GetRemainCD 使用节点 +0x10/+0x18；这些与同步结构的 +0x440、+0x18/+0x20 不同。尚无匹配的技能继续显示同步诊断，不能宣称所有普通/召唤师技能都已覆盖。

新增 logic_skill_address、logic_cd_node_address、logic_cooldown_read_ok、logic_cooldown_reason 和 logic_remain_raw；cooldown_source 明确最终显示值来自原生逻辑还是同步缓存，cooldown_node_address 指向对应来源。零值继续“待核”，不代表可释放。不使用 start+total−游戏时间补值，不记录/自行递减历史冷却。原生节点锁定字节按原 GetState 指令语义处理：+0x10 字节任意非零即锁定（ldrb/cbz），与同步路径的非零规则一致，不再拒绝大于 1 的字节值。

静态证据确认两套节点是同一数据的不同表示：引擎节点（技能 +0x590）锁定 +0x10、剩余 +0x18、总时间 +0x20、起始 +0x28（引擎 getter 0x1015164/0x101516c/0x101517c 与 GetState/GetStateSync 0x1014ff4/0x10150ac）；同步镜像（技能 +0x440）为引擎数据整体 +8（锁定 +0x18、剩余 +0x20、总 +0x28、起始 +0x30，见 get_remainTime/get_totalTime/get_startTime）。0.8.4 实机追踪证实：敌方普通技能的引擎节点剩余随时间递减（同一英雄镜像剩余保持为零），即 0.8.3 的零值来自同步镜像不更新而非游戏状态；logic_node_values_read_ok、logic_total_raw、logic_start_raw 原始读取仅诊断不参与显示。

敌方召唤师技能不在原生管理器 +0x2d8 列表中。原生召唤师管理器候选路由：A 为逻辑英雄 +0x360（消费者 0xff8b28），B 为管理器 +0x140 根对象（镜像同步路径中已工作的 +0x140 路由）；两者列表均为 +0x60/+0x68（8 字节条目，允许空槽，与原生 GetSkill 0x1001d60 的跳过行为一致），条目资源 ID 在 +0x74（资源 getter 0xfefc48）；同步对应物为同步英雄 +0x198、列表 +0x48/+0x50、资源 +0x44（0x1001e60/0xfefc50）。召唤师条目复用同一受身份校验保护的触发器/节点读取（+0x580 拥有者、+0x590 节点）；若对象实际不带此布局，读取会失败关闭并保留同步诊断，不会显示错误数据。失败原因分阶段区分：summoner_manager_unavailable（两条路由的根都不可用）、summoner_list_unavailable（根存在但 +0x60 列表校验失败）、skill_not_found。

0.8.4 实机显示路由 A 的英雄 +0x360 为空（logic_summoner_manager_address 0x0）。英雄级诊断新增 logic_summoner_manager_address/ok、logic_summoner_list_ok 与 logic_manager_slots：对管理器 +0x140/+0x158/+0x1d8/+0x1e8/+0x270/+0x278/+0x280/+0x308/+0x310/+0x360 十个原生级联槽位做只读指针导出（read_ok 区分空与不可读），下一轮实机直接定位召唤师技能所在路由。

0.8.3 报告开头的 not_in_battle 是早于实际 HUD 追踪的探测；空快照的 classification_reason 改为 snapshot_unavailable，避免误报分类 ready。

0.8.5 面板固定只显示确认的大招与召唤师条目，隐藏普通和未分类条目；原始 skills 数组保持完整，display_skills 是实际显示内容，分别记录 hidden_regular_count / hidden_unknown_count。名称来自原始 ENUM_SUMMON_SKILL_TYPE，覆盖疾跑、雪球、治疗、清晰术、屏障、虚弱、闪现、引燃、惩戒及枚举中的特殊模式变体；不通过槽顺序猜名称。之前 81100101 被误写为惩戒，已按枚举和原始引燃初始化指令纠正。
